# Offline coordinated renewal

The helper is additive and does not change the ten-file installed runtime pin. It renews the certificate against the existing TLS key and signs the new peer manifest with the existing application identity. It cannot recover from a compromised key; that requires a separately authorized identity migration. It validates expired historical certificates at their original validity start solely for identity continuity, never for active transport. New certificates must be currently valid, advance the expiry, and preserve the exact public key and profile.

Before activation, obtain the other device's renewed signed public manifest over an authenticated owner-approved path. On each device, use its existing service controller to perform a verified kill/stop, keeping its deny marker. Do not remove service metadata manually. Use the new helper's plan command to check both proposed certificates and obtain an exact plan digest. Apply only that approved digest. The helper stores a private recovery journal before replacing the four public/config files and keeps the owner policy disabled and kill marker intact. A partial failure remains denied; rollback takes the same plan digest and refuses unexpected concurrent changes. An existing journal must be reconciled/archived by the owner before a later rotation. Restart and clearing the kill switch are separate explicit owner actions, after both endpoints' new pins match. The F110 renewal is staged only; this does not claim Motorola renewal or communication.

Commands: node certificate-rotation.cjs renew STATE NEW_PUBLIC_FILE; plan STATE OWN_PUBLIC PEER_PUBLIC; apply STATE OWN_PUBLIC PEER_PUBLIC DIGEST; rollback STATE DIGEST. The renew command requires an expiry advance; default certificate duration is seven days. The three dedicated physical-F110 tests use isolated disposable identities and do not alter the existing live state.
